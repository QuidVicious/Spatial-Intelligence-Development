## How we work

- Don designs, sets requirements and tests on real locations. Claude writes the code. Every decision goes into DECISIONS.md, in Base (the repo root, above Dual-Pipeline and LSA-Studio).
- Don commits and pushes with GitHub Desktop at each major step and asks for a commit summary and description.
- The chat is linked to Don's PC through the Claude desktop app: Claude writes files straight into the folders and checks each file's size after writing. Use a new staging folder for every delivery (a second write from the same staged path once wrote a stale file).
- Standing rules: no em dashes; critical analysis and pushback; flag overclaims and gaps between recollection and record; ask before detailed output; lore and internal names stay out of public copy; always credit Google and Cesium; never reveal the locations of Antony Gormley's "6 Times" figures.
- Code is location-agnostic: no place-specific wording in hard-coded prompts or lists (it has fought other places before, Santa Fe the example).
- Deliveries name the folder for every file and list every file changed. Re-send texts in the current message; Don loses things scrolling back.
- In the UI, one step at a time: name the card and control, then wait for Don's confirmation.
